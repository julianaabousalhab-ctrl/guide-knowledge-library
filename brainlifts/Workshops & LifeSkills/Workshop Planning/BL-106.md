# Decompose Before You Design — Skill → Subskill → "I Can" Behaviors → an Activity That Forces Them

## Pattern

Strong workshop design runs a fixed decomposition order, and the activity comes last, not first:

1. **Life skill → one subskill** — a subskill of the chosen skill, from the LifeCore Knowledge Tree, not a second skill.
2. **Subskill → 2–3 observable standards** — the "I can…" statements for the grade band ("Strategy Switching — I can try a new approach when my first attempt doesn't work").
3. **Standards → activity** — the theme is chosen *because* it "naturally requires students to demonstrate use of the chosen life skill"; the template makes the designer justify that link in writing.
4. **AlphaTest written first, assembled from those same behaviors** — then baseline and checkpoints derived from the AlphaTest using one of two frameworks (continuous progress: 40% → 65% → 90% of the task; or component mastery: one AlphaTest component per checkpoint), with the explicit constraint that checkpoints "gradually build toward the T2P without changing the meaning of success."
5. **Any standard not visible in the AlphaTest must be covered explicitly in lessons and checkpoints** — the chain is closed; no chosen behavior is left unassessed.

The mechanism: when the behaviors are fixed before the activity, every later element — AlphaTest, baseline, checkpoints, lessons — can be derived instead of invented, and the workshop assesses what it claims to teach. When the activity comes first, the skill gets retrofitted to whatever the activity happens to produce.

Related: this is the upstream design step the rest of the Workshop node consumes — BL-071 publishes the resulting criteria to students, BL-103 measures the resulting baseline, BL-088 rehearses toward the resulting AlphaTest, BL-090 reviews the resulting failures. The tracker architecture in BL-102/BL-103 is this chain's tracking surface.

## Evidence

*1- The chain, prescribed step by step with its guardrail*

The planning guide runs exactly this order (skill → subskill → standards → activity context → AlphaTest first → baseline/checkpoints → lessons serving the current checkpoint) and names the ordering rule for the tempted: "if you already have an activity for a workshop in mind… you should still start your workshop planning process by identifying the lifeskill you will be assessing through that activity."

*2- The chain executed end-to-end in a real workshop design*

Record Breakers is traceable through every link: Grit → Keep Going → three "I can" standards (Strategy Switching, Sustain Attention, Progress Focus) → a Guinness World Record challenge chosen to force them → a AlphaTest that literally contains the behaviors ("≥30% improvement over their initial baseline… using at least two different strategies and sustaining effort in a continuous effort block of 15 minutes or more") — with the uncovered standard handled per the rule: "the 'progress focus' is measured in lessons and appropriate checkpoints."

## Anti-Pattern

The anti-pattern is activity-first design: a fun theme selected, with the life skill named afterward and the struggle it produces left unexamined.

*1- A documented activity-mismatch failure*

The Money Machines case (recorded in BL-090's evidence): an engaging entrepreneurship activity whose earn-back timeframe did not fit K–5 students — "they failed Test2Pass — repeatedly, across all of OC and other campuses, with some campuses never recouping at all" — resolved structurally by moving the activity to middle school, where the challenge window matches the students. The activity produced struggle, but not the *right* struggle for the age band.

Source artifact: cross-reference BL-090 (Feathers and Fix quote)

*3- The design doc's own named temptation*

The planning guide's warning to activity-first planners (quoted in Evidence 1) documents that the failure mode is common enough to legislate against in the standard process.

## Reusable Coaching Move

Run the Decomposition Check before committing to any workshop design:

1. **Name the chain in one line:** skill → subskill → the 2–3 "I can" statements. If you can't, you're not ready to pick an activity.
2. **Interrogate the activity:** "Why does this activity *naturally require* these behaviors?" — write the answer; if it needs adult enforcement to produce the behaviors, pick a different context.
3. **Write the AlphaTest first,** from the behaviors; derive baseline and checkpoints (continuous-progress or component-mastery), keeping the meaning of success constant.
4. **Audit coverage:** any "I can" statement not visible in the AlphaTest must appear explicitly in lessons and checkpoints.

## Confidence: Medium — a prescriptive chain corroborated by one fully traceable executed exemplar, institutionalized tooling, and the live tracker architecture at ~20 campuses; only one end-to-end exemplar document so far, and no corpus comparison of decomposition-first vs activity-first workshop outcomes beyond the cited mismatch case.
