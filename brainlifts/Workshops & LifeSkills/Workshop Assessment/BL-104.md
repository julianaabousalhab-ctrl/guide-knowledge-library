# "Not Passed" Is a Diagnosis Trigger, Not a Terminal State — Close Every Failed AlphaTest With the Gap and the Path

## Pattern

When a student fails an AlphaTest, the strong Guide practice writes a closure note in the same row as the result, with two components:

1. **The component-level gap** — which specific part of the assessment fell short, stated against the criteria, and often alongside what the student *did* achieve ("hit the park rating and revenue goals, but came up short on the economic reflection of why he was successful").
2. **The forward path** — a retry condition, extension, or continuing coaching plan ("can retry after coaching feedback session"), so the failure ends as a paused sequence rather than a verdict.

The tracker vocabulary shows the retry path institutionalized where the practice is strongest: result states like "Passed Attempt 1" and "Extended" only exist in a system where a first failure is expected to be re-attempted.

The mechanism: a bare "Not passed" tells the student, the next Guide, and the parent nothing about what to do — it stores the outcome and discards the information the assessment produced. The closure note converts the most expensive data point in the workshop (a full-conditions failure) into the next intervention. This is the individual complement to BL-090: after the cohort-level check for shared causes, each non-passer still needs a personal diagnosis and path.

Related: BL-090 (mass failure → system review) handles the cohort question first — if many students failed the same AlphaTest, the gap is the workshop's, not each student's. BL-088 governs preparation before AlphaTest day; this pattern governs closure after it. BL-044 is the same continuity principle at Launch scale. BL-036's repair logic (name the gap, define the path back) is the behavioral parallel.

## Anti-Pattern

The anti-pattern is logging the failure and stopping: "Not passed" recorded with no gap, no path, nothing.

*1- Measured in this corpus*

176 of 537 non-passing students (33%) have a bare "Not passed" with no closure note — for these students the assessment produced a verdict and no usable information, and any retry depends on someone remembering.

Source artifact: Workshop Skill Trackers SY25-26 — AlphaTest vs Post-AlphaTest columns, corpus-wide count

*2- Where the pattern's absence leads, from the library*

BL-090's anti-pattern corpus documents the end state: shared failures recorded individually, month after month, with the pattern never triggering diagnosis — failure data accumulating as verdicts instead of information.

Source artifact: cross-reference BL-090, Anti-Pattern evidence

## Reusable Coaching Move

Close every AlphaTest row the day of the assessment:

1. **Cohort check first (BL-090):** did enough students fail the same AlphaTest to trigger a system review? If yes, run that before writing individual diagnoses.
2. **For each non-passer, write the gap:** which criterion component fell short — and which components were met (the "hit X, short on Y" frame).
3. **Write the path:** retry date and condition ("after coaching feedback session"), extension, or the specific coaching that continues — an entry another Guide could act on.
4. **For passers, when raising the bar (optional extension):** name the next stretch in the same note.

## Confidence: Medium — 361 instances across 37 campus-level trackers with a measured 33% anti-pattern base rate and institutionalized retry states; the corpus does not track whether noted non-passers ultimately passed on retry, so the outcome claim rests on the mechanism.
